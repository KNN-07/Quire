Quire Server

Host it yourself.
Keep control.

The editor, Git, identity, and optional AI integrations, on servers you manage. There is no license key and no commercial feature gate. Each capability still needs its runtime dependencies.

BUN="$PWD/node_modules/.bin/bun"
"$BUN" run build

Three ways to install

All three start from a source checkout. None of them ships credentials or a preconfigured production release.

Native

One machine, using the local profile: SQLite, local blobs, and Git repositories. Run the commands from the repository root. The destination must not already exist, and installation does not overwrite data or enable a system service.

Terminal
bun install --frozen-lockfile
BUN="$PWD/node_modules/.bin/bun"
"$BUN" run build
PREFIX="$HOME/quire-server"
"$BUN" scripts/ops/install.ts --source "$PWD" \
  --prefix "$PREFIX" --bun "$BUN" --port 43181
"$PREFIX/bin/quire" serve

Open the service on port 43181. In a second terminal, run $HOME/quire-server/bin/quire doctor to check the running installation and the confined compiler.

Docker Compose

Two API coordinators, a single Git repository role, PostgreSQL, Redis, and authenticated S3-compatible storage. You supply a private environment file, pinned platform images, persistent volumes, TLS, and isolated workers.

Terminal
docker build -f deploy/runtime/Dockerfile \
  -t quire-owned-app:release .
docker compose --env-file "${COMPOSE_ENV:?Set your private compose.env path}" \
  -f deploy/compose/compose.yaml config --quiet
docker compose --env-file "$COMPOSE_ENV" \
  -f deploy/compose/compose.yaml up --build --wait --wait-timeout 180

The supplied image manifest targets Linux/amd64. API ports bind to loopback, so put your own TLS reverse proxy in front.

Kubernetes (Helm)

The chart lives in deploy/helm. There is no public chart repository. Your values file supplies the application image, the runtime, TLS and signing secrets, and shared backup storage.

Terminal
helm lint deploy/helm \
  -f "${QUIRE_HELM_VALUES:?Set your operator values file}"
helm template quire-owned deploy/helm -f "$QUIRE_HELM_VALUES"
helm install quire-owned deploy/helm \
  --namespace "${QUIRE_NAMESPACE:?Set your owned namespace}" \
  -f "$QUIRE_HELM_VALUES" --wait --wait-for-jobs --timeout 5m

Provision cluster storage, the database, Redis and S3 endpoints, ingress with TLS, and worker isolation before you install.

Signed, controller-owned updates are supported for the native systemd-local-v1 driver. Compose and Helm use their own documented deployment and recovery procedures.

What runs on your server

The default profile is one API and real-time coordinator, a built web client, and a separate isolated compile worker.

Runtime
Bun 1.4.4, Git, and Linux for isolated compilation. Building the web client also needs Node.js ^20.19.0 or >=22.12.0.
Compilation
TeX Live, latexmk, and a verified Bubblewrap or Docker sandbox with its resource-containment prerequisites.
Storage
Persistent directories for SQLite, blobs, and repositories, or the PostgreSQL, Redis, and S3 scale profile.
Hardware
There is no measured production sizing recommendation yet. Compile budgets are configurable. The default job memory budget is 1 GiB.

Web and API

The browser interface and the Bun HTTP coordinator.

Real-time sync

Authorized collaborative document transport.

Git repositories

Repository objects and working checkpoints for each project.

Compile workers

An installed TeX distribution running in verified isolation.

AI gateway

Optional. One endpoint and model that you configure.

Identity provider

Optional. SAML, OIDC, or LDAP with your own configuration.

AI on your terms

Bring your own model, or none

Point the assistant at a model in your own data centre or at a provider you approve, or leave it unconfigured. Writing and compilation do not need it.

  • Requests go only to the endpoint you configure
  • The operator holds the credentials
  • Citation search needs its own provider configuration

Disconnected sites

Build a signed offline bundle

Repository tooling creates and verifies signed bundles of the runtime, dependencies, and images, using your own Ed25519 signing key.

Offline and recovery instructions

Offline bundle commands

Offline bundle
BUN="$PWD/node_modules/.bin/bun"
"$BUN" scripts/ops/airgap.ts create --source "$PWD" \
  --output "${QUIRE_BUNDLE:?Choose a new bundle directory}" --bun "$BUN" \
  --signing-key "${QUIRE_SIGNING_KEY:?Set your private signing key}" \
  --environments "${QUIRE_ENVIRONMENTS:?Set executed environment manifests}" \
  --image "${QUIRE_APPLICATION_IMAGE:?Set your verified application image}" \
  --image "${QUIRE_POSTGRES_IMAGE:?Set your PostgreSQL image}" \
  --image "${QUIRE_REDIS_IMAGE:?Set your Redis image}" \
  --image "${QUIRE_S3_IMAGE:?Set your S3 image}" \
  --image "${QUIRE_TOOLCHAIN_IMAGE:?Set your verified toolchain image}"
"$BUN" scripts/ops/airgap.ts verify "$QUIRE_BUNDLE" \
  --public-key "${QUIRE_TRUSTED_KEY:?Set the separately trusted public key}"

Private signing keys, production secrets, and data are not included in a bundle. Offline packaging does not make external identity, model, or reference services available offline.
