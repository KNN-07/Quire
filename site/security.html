Security

How Quire protects your work

Quire runs on infrastructure you control. This page describes what the software does by default and what remains the operator's responsibility.

Built in

Sessions

Signing in sets an HttpOnly session cookie with SameSite=Lax, marked Secure under HTTPS. State-changing requests need a matching origin and a per-session CSRF token. Passwords are hashed with Argon2id.

Compilation

LaTeX runs in an isolated worker with no network access, a read-only source mount, and memory, process, and time limits. There is no unsandboxed fallback.

Outbound requests

Quire's safe HTTP transport and remote Git HTTPS connections use public addresses and pin connections to the resolved address. The safe HTTP transport requires HTTPS for requests carrying credentials. LDAP uses a separate transport with explicitly approved directory URLs and verified TLS (LDAPS or StartTLS).

Stored credentials

Provider tokens and secrets are encrypted at rest with AES-256-GCM and bound to the record that owns them. Git access tokens are stored only as hashes.

Assistant edits

The assistant proposes changes. Nothing is written to a project until someone with edit access accepts the proposal.

Backups

Backups are signed with an Ed25519 key that you provision separately from the application's own secret.

Your responsibility as operator

Self-hosting means the deployment's security is yours. Quire does not manage these for you.

  • TLS termination and the reverse proxy in front of the API
  • Keeping the host, container images, and TeX distribution patched
  • Provisioning and rotating the application secret and backup signing key
  • Choosing identity, mail, AI, and storage providers and their retention
  • Network isolation between the API, workers, and data stores

Known limits

Quire is in active development and has not had an independent security audit. Password sign-in has no built-in second factor; use a configured identity provider if you need one. Sign-in attempts are throttled per account, not per network address.

Browser Python is opt-in and runs in your browser, not on the server. Its worker has its network and shared-storage access removed before a script starts, but it shares the application's origin, so run only scripts from collaborators you trust.

Reporting a vulnerability

Please report security issues privately through the repository's security page and avoid opening a public issue for anything exploitable.
