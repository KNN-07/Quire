Run and operate Quire

Start a local workspace in a few commands, then follow the runbooks for deployment, integrations, and recovery.

Quick start

You need Bun 1.4.4, Node.js ^20.19.0 or >=22.12.0, and Git. Compiling PDFs natively also needs Linux with a TeX distribution; see Compilation.

Terminal
git clone https://github.com/KNN-07/Quire.git
cd Quire
bun install
bun run db:migrate
bun run seed
bun run doctor
bun run dev

Open http://localhost:5173 and sign in as kien@quire.local with the password that bun run seed prints. The development operator account is operator@quire.local with the same password. Create a blank project or start from the Starter Article template.

The first compiler readiness check can take about 45 seconds. Project data is stored in .data.

The install includes a repository-local Bun binary. Use the package scripts or ./node_modules/.bin/bun so an older global Bun is not used by accident.

Configuration

Copy .env.example and adjust it. These are the settings most installations change.

VariableDefaultPurpose
QUIRE_DATA_DIR.dataWhere the database, blobs, and repositories live. Use the same directory for migration, seeding, startup, and diagnostics.
QUIRE_HOST127.0.0.1Address the API listens on.

Compilation

PDFs are compiled by an isolated worker, never in the API process. Native compilation needs Linux, TeX tools, BibTeX or Biber, SyncTeX, Poppler, Bubblewrap, and a working systemd user service. bun run doctor checks the toolchain and the sandbox; an executable being present is not enough to pass.

  • Compiler environmentsInstalling TeX tools, probes, and custom environments.
  • Compiler workersWorker processes, limits, and remote workers.

Deployment

The development command is not a production installation. Pick a profile and follow its guide. The self-hosting page has the install commands for each.

Integrations

Every integration is optional and unconfigured until an operator sets it up: an AI provider, SAML, OIDC or LDAP sign-in, reference providers, remote Git hosts, Dropbox, outbound mail, and billing. ReadCube and Dimensions are not available.

  • Adapter configurationConfiguring and testing each provider.
  • SSH Git bridgeGit over SSH for project repositories.
  • Project creation and importTemplates, ZIP, and Git import choices.

Operations

Backups are signed and cover the database, blobs, and repositories together. Do not copy a live SQLite file on its own.

  • Backups and recoveryCreating, verifying, and restoring full backups.

Development

Run the checks before you send a change. Browser and compiler suites need Chromium and the TeX toolchain, so run the ones relevant to your change.

Terminal
bun run typecheck
bun run lint
bun run build
bun run verify:matrix
./node_modules/.bin/bun test tests/contract

The server composition lives in apps/server, the web client in apps/web, shared contracts in packages, and features in services.
