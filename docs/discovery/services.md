The research consists of public-documentation verification. No authenticated invitation, concurrent edit, synchronization, AI call, payment, SSO exchange, deployment, recovery, or security audit was executed. Acceptance ideas in the tables are proposed future tests, not passing test results.

Classification:

- **Build**: a concrete capability that can be implemented in Quire.
- **Policy**: an Overleaf price, entitlement, commercial arrangement, support process, or legal statement. Build the underlying rule/configuration mechanism where needed; do not silently copy the vendor's business terms as Quire requirements.
- **Boundary**: a documented restriction, uncertainty, or conflict. It must remain explicit rather than becoming an invented guarantee or a silently omitted feature.
- **Retired / experimental / future**: preserve the distinction from currently documented functionality.

Rows can contain all three main classifications: for example, quotas are buildable, but Overleaf's numerical plan thresholds are business policy. “Unspecified” never means “absent.” Hosted Pro, hosted Group Pro, Commons, Commons AI, Community Edition (CE), and commercial self-hosted Server Pro are distinct scopes.

## Permission and security invariants

The following are Quire design/acceptance requirements inferred from the behaviors above, not claims of an audited Overleaf implementation:

1. **Authorize every surface.** File reads/downloads, WebSocket edits, comments, suggestions, history exports/restores, chat, sync, and AI context access must evaluate project access server-side. A hidden control is not authorization. Tokens do not confer rights beyond their principal/current project access.
2. **Separate access dimensions.** Represent owner, named role, token access, group administrative role, licensed membership, managed-account status, institutional eligibility, account tool entitlement, and deployment capability independently. Group admin does not imply project access in ordinary hosted user-controlled accounts; self-host operators and managed organizations have separately disclosed powers.
3. **Protect role boundaries.** Viewer cannot mutate content/comments; Reviewer cannot create files, enter ordinary Editing, accept/reject, or restore. Explicitly specify any unsettled thread moderation permission. Owner-only linked bibliography re-sync and ordinary transfer are distinct from authorized administrative transfer.
4. **No elevation through requests or links.** Pending access/invitation requests confer no higher role. Revoke link access without dropping named invitations. Organization policy may tighten sharing; its prospective-versus-retroactive scope must be explicit. Do not claim downloaded-copy recall.
5. **Re-evaluate entitlement at transitions.** Owner transfer, premium downgrade, Commons eligibility loss, group removal, management release, and deployment changes must not delete project content as a side effect. Recompute writable roles and review/compile/history access without implying collaborators inherited every account integration.
6. **Keep reversible and destructive actions separate.** Resolve versus delete comment, trash versus leave versus permanently delete project, remove/release versus delete managed user, restore source versus restore operator backup. Transfers/deletions must not strand ownerless projects or silently destroy unrelated shared projects.
7. **Document convergence and recovery separately.** Source convergence is not guaranteed persistence, backup, low latency, or review-metadata preservation. Proposed concurrency tests need explicit acknowledgement/event boundaries, not timing luck.
8. **Credential isolation.** Each external account owns its consent/tokens; do not share collaborator Git tokens or expose provider secrets in client bundles, chat, project files, logs, source ZIPs, or prompts. Store application/provider secrets in a deployment secret store and user grants in protected server-side storage; redact logs and support revocation. These are Quire requirements, not documented Overleaf storage assurances.
9. **Constrain external fetch.** Imported URLs and AI/provider payloads are system boundaries. Define supported content, byte limits, redirects and network destinations; prevent access to internal service credentials/addresses. A public link may expose project material; do not bypass a provider's authentication gate by asserting a working import.
10. **Consent before disclosure.** AI tool disabled by user/organization or lacking required first-use acceptance must not send context externally. Enforce relevant project permission and cross-organization policy before selecting source/log/error payload. Disclose processor scope and terms; do not claim zero retention/local-only/unconditional no-training without a separate substantiated contract.
11. **Robust identity controls.** Validate email ownership and federation issuer/audience/signature/expiry/replay protections; certificate rotation must not become trust-all. Resolve the chosen SAML signature policy explicitly while retaining the research contradiction. IdP user deletion does not imply application deprovisioning.
12. **Audit privileged changes without inventing user audit coverage.** Record management, feature policy, ownership, billing and session actions for authorized operators; export only permitted audit data. Research does not establish universal hosted per-access logging, token rotation, or recipient notifications.
13. **Untrusted compilation requires real isolation.** Do not present CE-like unsandboxed subprocesses as equivalent to restricted compile containers. Privileged socket exposure, resource controls, timeouts, command allowlists and network policy need explicit verification.
14. **Backup completeness is explicit.** Configuration/source export cannot be labeled a complete backup. Quiescent database, pending collaboration state and project/history stores must restore coherently; restore drills establish only measured outcomes, not a generic RPO/RTO.
15. **No counterfeit integration success.** Missing credentials, provider outage, unsupported linkage, exhausted allowance, unresolved licensing or missing feature results in a truthful unavailable/error state. A local mock can test a contract but is not a delivered external integration.
